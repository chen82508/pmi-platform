# pmi-demo

A small synthetic market world that replaces live exchange ingestion. Every
market is invented, but titles use real venue phrasing so the engine's title
grammars (country aliases, Senate race patterns, strike ladders) parse them
exactly as they would live data.

`fixtures/markets.json` is generated by
[`generate_fixtures.py`](generate_fixtures.py) (seeded, reproducible):

| Set | Markets | Exercises |
|---|---|---|
| Conflict | 10, across 3 venues incl. one play-money | country extraction, geography-weighted rollup, direction (escalation vs peace), a keyword false positive that relevancy filters out |
| Bitcoin | 7-strike Kalshi ladder + 1 Polymarket touch market | strike parsing, implied spot, log-moneyness kernel, signed average |
| US Senate 2026 | all 35 seats, both party legs where contested | race-tag classification, party direction, Poisson-binomial projection |

Fields beyond the usual market columns:

- `price_history`: 14 daily prices before `last_price`. `pmi-core seed`
  writes them as `ts_price_snapshots`.
- `closes_in_days`: close time relative to seeding, so the demo never expires.
- `judgements`: factor answers, e.g. `{"armed_conflict": 1,
  "war_direction": -1}`. The `fixture/` LLM provider
  (`pmi_core/llm/fixture_client.py`) replays them; unlisted factors answer 0.

```bash
pmi-core seed                  # markets + price history + index definitions
pmi-core demo bind             # bind unbound factors to fixture/labels
pmi-workers run tag-races      # classify Senate race legs
pmi-core demo history          # one scored point per day for 14 days
pmi-core dry-run <def.yaml>    # same answers, in-process, no database
```

`demo bind` never replaces a factor that already has a production model, so
real bindings coexist with the demo.
